# Scrolling plan

Explored `https://webdriveruniversity.com/Scrolling/index.html` (title `WebDriver | Scrolling`) in Chromium at the suite's Desktop Chrome viewport, 1280×720, through the existing bot-wall path. The heading is `Just Scrolling Around!`. There are no fields. The four boxes are `div.thumbnail` elements. None has an accessible name.

| Zone             | Where it sits at 1280×720                                       | What the page actually does                                                                                                                                                                                                                                                                                                                                                                              |
| ---------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First (`#zone1`) | In view, about y 197–297                                        | The heading is `Scroll to me first!`. `mouseover` sets the box text to `Well done for scrolling to me!`, `font-size` to `24px`, and `text-align` to `center`. `.text()` removes the heading. There is no `mouseout`.                                                                                                                                                                                     |
| Left (`#zone2`)  | In view, the left half of the row, about y 497–597              | The heading `#zone2-entries` reads `0 Entries`. `mouseenter` sets it to `1 Entries`, then `2 Entries`, and so on. The count is closed over in this handler only. Leaving the box does not reset it. A second `hover()` while the pointer is already inside does not add one.                                                                                                                             |
| Right (`#zone3`) | In view, the right half of the same row                         | Same markup and the same handler, with its own `en` starting at `0`. Entering it does not change the left count.                                                                                                                                                                                                                                                                                         |
| Last (`#zone4`)  | Fully below the viewport. Top is about 797; the viewport is 720 | The heading is `Dont forget to scroll to me!` (no apostrophe). Scrolling it into view does not change that text. `mouseover` replaces the box with `X: ` + the horizontal offset + `Y: ` + the vertical offset, and sets `font-size` to `32px`. A hover at the center produced `X: 625Y: 847` on this viewport. There is no space before `Y`. There is no `mouseout`. The numbers move with the pointer. |

`css/subpage.css` sets `background-color` and `color` to `revert !important` on `html body #zone1` through `#zone4`. The script still writes a green background on the first zone and a black background with white text on the last zone, and those declarations are on the element. The computed background stays transparent and the computed color stays `rgb(237, 237, 237)`. The page does not show those colors. `font-size` is not reverted, so 24px and 32px are visible.

Locators, in the project order: the page heading and the zone headings are headings. The two entries headings share the name `0 Entries`, and that name changes, so each count is the heading inside its zone. The zones have no accessible name. Each id is unique, so the id is the locator. `#myModal` is in the page and nothing opens it. `myFunction` alerts and is never called.

## Cases

Tags: `@scrolling` on the describe block, `@regression` on every test. `@smoke` on the two scroll-to-me messages, so those tests carry both. The entries counter is the other widget and stays regression.

| Case                                                              | Category | Priority | Tags                   | What it checks                                                                                                                                                                                   | Why this one                                                                                                                                                                            |
| ----------------------------------------------------------------- | -------- | -------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| hovering the first zone shows the success message                 | Positive | Critical | `@smoke` `@regression` | The heading is `Scroll to me first!`. After the hover the zone reads `Well done for scrolling to me!` and its font size is `24px`.                                                               | The only exact success sentence. The zone is already in view, so this is the smallest check that `mouseover` ran. It is one of the two `@smoke` tests.                                  |
| hovering the last zone shows pointer coordinates                  | Positive | Critical | `@smoke` `@regression` | The heading is `Dont forget to scroll to me!`. After the hover the zone text matches `X:` + digits + `Y:` + digits, and the font size is `32px`.                                                 | This is the box below the fold. The hover scrolls it into view and the text change is the outcome. The digits are not asserted. It is the other `@smoke` test.                          |
| hovering the left entries box counts one entry                    | Positive | High     | `@regression`          | Both counts start at `0 Entries`. Entering the left box shows `1 Entries`. The right box stays at `0 Entries`.                                                                                   | The left box's only success path. The right count shows the handlers do not share one number.                                                                                           |
| hovering the right entries box counts one entry                   | Positive | High     | `@regression`          | The right box starts at `0 Entries`. Entering it shows `1 Entries`. The left box stays at `0 Entries`.                                                                                           | The right handler is a second copy with its own counter. The left test still passes if `#zone3` never increments.                                                                       |
| scrolling to the last zone leaves its text                        | Negative | High     | `@regression`          | The last zone is not in the viewport and reads `Dont forget to scroll to me!`. After it is scrolled into view it is in the viewport, the window has scrolled down, and the heading is unchanged. | The label tells you to scroll. The hover test scrolls as part of `hover()`, so it would still pass if scrolling itself rewrote the text.                                                |
| entering the left entries box again counts another entry          | Edge     | High     | `@regression`          | The first enter shows `1 Entries`. The pointer leaves the box, and entering again shows `2 Entries`. The right box stays at `0 Entries`.                                                         | The count is per enter, and leaving does not reset it. A second enter that shows `2 Entries` is the check that the count was not cleared. The one-entry test only sees the first enter. |
| the first zone keeps the success message after the pointer leaves | Edge     | High     | `@regression`          | After the success message is shown, moving the pointer to the left entries box shows `1 Entries` and leaves `Well done for scrolling to me!` and the `24px` font.                                | There is no `mouseout`. The success test checks the text while the pointer is still on the zone. The left count shows the pointer has left.                                             |

## Not selected

| Category                                           | Reason                                                                                                                                                                                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact `X` and `Y` numbers                          | They are `pageX - offsetLeft` and `pageY - offsetTop`. A center hover was stable in one look (`X: 625Y: 847`) and would move if the font, the scroll, or the viewport shifted. The shape of the text is the outcome.                                    |
| Green background, black background, white text     | The script sets them. `subpage.css` reverts `background-color` and `color` with `!important`, so the page does not show them. Asserting the computed color would fail on the stylesheet, not on the handler. Font size is the style the page does show. |
| The last zone keeps its coordinates after mouseout | Same missing `mouseout` as the first zone. Checking that the coordinate string stayed would either repeat that edge or pin the numbers.                                                                                                                 |
| A click that does not move the pointer             | A real click moves the pointer first, so it also runs `mouseover` or `mouseenter`. Dispatching `click` with no move leaves the first zone unchanged, and that is not a gesture a person can make.                                                       |
| A second hover while the pointer is already inside | `mouseenter` does not fire again. `hover()` at the same point is not a second gesture. Leaving and entering again is the edge a person can do.                                                                                                          |
| Empty, invalid, or whitespace input                | No fields and no form. Nothing to reject.                                                                                                                                                                                                               |
| Keyboard activation                                | The boxes are divs. The listeners are `mouseover` and `mouseenter`. Tab reaches the navbar brand. A keyboard failure would be a new requirement, not a broken one.                                                                                      |
| `#myModal` and `myFunction`                        | Nothing in the page script opens the modal or calls the alert.                                                                                                                                                                                          |
| Navbar brand link                                  | Site chrome, not a scrolling outcome.                                                                                                                                                                                                                   |
| Mobile widths                                      | The suite runs Desktop Chrome only. Below the `lg` breakpoint the two entries boxes stack, and covering that would mean a config change.                                                                                                                |
