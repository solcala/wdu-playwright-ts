# Hidden Elements plan

Explored `https://webdriveruniversity.com/Hidden-Elements/index.html` (title `Hidden Elements`) in Chromium at the suite's Desktop Chrome viewport, 1280×720, through the existing bot-wall path. The heading is `Hidden Elements..`. There are no fields.

Each column is a heading plus a `.section-title` box. The page's own style sets `.section-title` to `height: 70px`. The control in each box is a span, not a button, with `tabIndex` `-1`. The labels are unique: `CLICK ME!`, `CLICK ME!!`, and `CLICK ME!!!`. Each span has `data-toggle="modal"` and points at a Bootstrap dialog that is in the page and hidden on load.

| Section           | Rule                                        | What the page actually does                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Not Displayed     | `#not-displayed { display: none }`          | The section and `CLICK ME!` (`#button1`) have an empty box. Playwright treats the control as hidden. `locator.click` waits until the action timeout. The span's modal is `#myModalClick` (`Congratulations!`). A normal click never reaches it.                                                                                                                                                                                   |
| Visibility Hidden | `#visibility-hidden { visibility: hidden }` | The section keeps a 358×70 box. `CLICK ME!!` (`#button2`) is hidden and is not a hit target. A pointer click in that box lands on the parent `div.thumbnail`. The span's modal is `#myModalJSClick`. It stays closed. `locator.click` on the span waits until the action timeout. Playwright's `boundingBox()` still returns this section's box.                                                                                  |
| Zero Opacity      | `#zero-opacity { opacity: 0 }`              | The section keeps a 358×70 box and its computed opacity is `0`. `CLICK ME!!!` (`#button3`) has its own computed opacity `1`, so the parent's opacity is what makes the label impossible to see. Playwright's visibility check ignores opacity, so `toBeVisible()` passes and a normal click hits the span. That opens `#myModalMoveClick`. The click does not change the section opacity. Close hides the modal. Escape does not. |

`js/script.js` is wrapped in a `<script>` element, so it is not valid JavaScript and does not run. `#dialog` stays `display: none`. The three spans are not in the tab order. The first Tab stop is the navbar brand link.

Locators, in the project order: the column headings are headings. The controls have no role; `getByText` with an exact label is unique. The sections and the modals have no accessible name, stay in the page while hidden, and each id is unique, so the id is the locator.

## Cases

Tags: `@hidden-elements` on the describe block, `@regression` on every test. `@smoke` only on the one control a normal click can activate, so that test carries both.

| Case                                                             | Category | Priority | Tags                   | What it checks                                                                                                                                                                        | Why this one                                                                                                                                                                                        |
| ---------------------------------------------------------------- | -------- | -------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| clicking the zero-opacity control shows its modal                | Positive | Critical | `@smoke` `@regression` | The section opacity is `0` and the control is visible to Playwright. The click opens `#myModalMoveClick`, with that title and the interactions sentence.                              | The only success path. Opacity `0` still receives the click, which is the trap on this page. It is the smallest critical check, so it is the only `@smoke` test.                                    |
| the not-displayed control is not shown                           | Negative | High     | `@regression`          | The heading is visible. The control is attached and hidden. The section's display is `none`. Its modal stays hidden.                                                                  | `display: none` removes the control. `toBeHidden()` alone would also pass for a missing node or for `visibility: hidden`, so the test checks that the node is present and that the rule is display. |
| a click on the visibility-hidden section does not open its modal | Negative | High     | `@regression`          | The control is attached and hidden, and the section's visibility is `hidden`. A pointer click at the center of that box hits `div.thumbnail`, not `#button2`. The modal stays hidden. | The box is still there, so a click is a real gesture. The hidden control does not receive it. A timeout from `locator.click` is not an outcome.                                                     |
| not displayed takes no space and the other sections keep theirs  | Edge     | High     | `@regression`          | The not-displayed section has no layout box. The visibility-hidden and zero-opacity sections each have height 70.                                                                     | The three rules do not look the same on the page. `toBeHidden()` does not tell a collapsed section from one that still occupies its row.                                                            |
| the zero-opacity control opens its modal again                   | Edge     | Medium   | `@regression`          | Close hides the modal. The section opacity is still `0`. A second click shows the modal again.                                                                                        | Close dismisses the modal. A second open shows the modal was dismissed and that the click did not reveal the control by changing its opacity.                                                       |

## Not selected

| Category                                         | Reason                                                                                                                                                                                                            |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Empty, invalid, or whitespace input              | N/A. There are no fields and no form. Nothing to reject.                                                                                                                                                          |
| Disabled or read-only controls                   | N/A. None of the controls are disabled.                                                                                                                                                                           |
| Keyboard activation                              | N/A. The spans have `tabIndex` `-1` and no key listeners. Tab reaches the navbar brand and does not reach a control. A keyboard failure would be a new requirement, not a broken one.                             |
| `locator.click` on the not-displayed control     | The element has no box. The click waits until the action timeout. The hidden check and the empty box cover that state. A timeout is not an outcome.                                                               |
| `locator.click` on the visibility-hidden control | Same timeout. The pointer click in the section's box is the rejected gesture.                                                                                                                                     |
| Forcing a click on a hidden control              | A forced click would skip the hit check and open the modal the page does not show. That erases the difference between the three rules. The zero-opacity control accepts a normal click, so no test needs `force`. |
| Escape, ×, and the overlay                       | Escape leaves the modal open. × and a click outside the dialog hide it. Those are the same Bootstrap paths already covered on Button Clicks. Close is the dismiss in the success test.                            |
| The other two modal bodies                       | A normal click never opens them. Their copy is not an outcome of this page.                                                                                                                                       |
| `#dialog` and `js/script.js`                     | The file is wrapped in a script tag, so it does not parse. The dialog stays `display: none`. Same class of dead script as Button Clicks.                                                                          |
| Navbar brand link                                | Site chrome, not a hidden-element outcome.                                                                                                                                                                        |
| Mobile widths                                    | The suite runs Desktop Chrome only. Covering the breakpoints would mean a config change.                                                                                                                          |
