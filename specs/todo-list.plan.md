# To Do List plan

Explored `https://webdriveruniversity.com/To-Do-List/index.html` (title `WebDriver | To Do List`) in Chromium at the suite's Desktop Chrome viewport, 1280×720, through the same browser-check wait the suite uses. The heading on the page is `TO-DO LIST`. The list is not stored anywhere: a new visit starts from the three practice items.

| Control   | What the page actually does                                                                                                                                                                                                                                                                                                                                                                   |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Add field | One text input. Its placeholder `Add new todo` is the accessible name. There is no label and no Add button. `keypress` with `which === 13` reads the value, clears the field, and appends `<li><span><i class='fa fa-trash'></i></span> ` plus that value. Empty and whitespace values are appended too. The value is not trimmed.                                                            |
| Plus icon | `#plus-icon` is `aria-hidden`. The click handler is `.fa-plus`, and it calls `fadeToggle()` on the input. It does not add a row.                                                                                                                                                                                                                                                              |
| Rows      | The list starts as `Go to potion class`, `Buy new robes`, and `Practice magic`. None have the `completed` class. A click on an `li` runs `toggleClass("completed")`. That class sets `text-decoration: line-through` and `color: gray` (`rgb(128, 128, 128)`). The resting color is `rgb(154, 154, 154)`.                                                                                     |
| Delete    | Each row has a `span` with no role and no accessible name. CSS keeps it at `width: 0` and `opacity: 0` until `li:hover`, then `width: 40px` and `opacity: 1` over 0.2s. The click handler is delegated on `ul` for `span`: `fadeOut(500)` and then `remove()`, and `stopPropagation()` so the row click does not also toggle `completed`. A click on the span before the hover does not land. |

The row click and the delete click are `$("ul").on(...)`, so a row added later uses the same handlers as the three practice rows.

`getByRole('textbox', { name: 'Add new todo' })` matches the field. The plus icon has no accessible name, so the locator is `#plus-icon`. The rows are `listitem`. The delete control is the `span` inside that row. Playwright still treats the 0-width span as visible, because its box is 40px tall, so the collapsed check is `width` and `opacity`, not `toBeHidden`.

## Cases

The describe block is tagged `@todo-list`. Every test is `@regression`. `@smoke` is the three changes a person can make to the list: add, strike through, remove.

| Case                                                  | Category | Priority | Tags                                | What it checks                                                                                                                                                                                    | Why this one                                                                                                                                                                   |
| ----------------------------------------------------- | -------- | -------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| the list starts with the three practice items         | Positive | High     | `@todo-list` `@regression`          | The list has `Go to potion class`, `Buy new robes`, and `Practice magic`. None are struck through. The field is visible and empty.                                                                | The practice rows are the page's content. The later tests change one row, so this is the only case that locks all three names.                                                 |
| entering a todo adds it to the list                   | Positive | Critical | `@todo-list` `@smoke` `@regression` | Enter on `Brew a potion` makes the count 4, shows that text, and clears the field. The three practice rows are still there.                                                                       | The only way to add. The count is what shows the row was appended, not typed into an existing one.                                                                             |
| clicking an item strikes it through                   | Positive | Critical | `@todo-list` `@smoke` `@regression` | `Buy new robes` gains `completed`, `text-decoration-line: line-through`, and `rgb(128, 128, 128)`. The count stays 3. The other two rows stay open.                                               | The strike-through is the completed state. The count stays so a click is not a delete. The other rows show the class was added to the one that was clicked.                    |
| the delete control removes that item                  | Positive | Critical | `@todo-list` `@smoke` `@regression` | `Practice magic`'s delete span starts at `width: 0` and `opacity: 0`. Hover opens it past `width: 0`, which is what the click needs. The click removes that row and leaves the count at 2.        | Removal is the other end state. The width is the condition the click waits for: the span is not actionable at `0px`, and `toBeHidden` does not describe it.                    |
| enter on an empty field adds a blank item             | Negative | High     | `@todo-list` `@regression`          | Enter on an empty field makes the count 4 and adds one row with no letters. The field stays empty. The practice rows stay.                                                                        | There is no validation and no error message. The blank row is the observed result, and the add test would still pass if an empty Enter were rejected.                          |
| clicking a completed item clears the strike-through   | Edge     | High     | `@todo-list` `@regression`          | After a click has struck `Buy new robes` through, a second click removes `completed`, returns `text-decoration-line` to `none`, and returns the color to `rgb(154, 154, 154)`. The count stays 3. | The handler is `toggleClass`, not `addClass`. The strike-through test only sees the first click.                                                                               |
| the plus control toggles the add field                | Edge     | High     | `@todo-list` `@regression`          | The field starts visible. One click hides it and leaves the count at 3. The next click shows it and the count stays 3.                                                                            | The icon is a plus, and the handler is `fadeToggle`, not an add. The add test never clicks it, so it would not catch a plus that appended a row or a field that stayed hidden. |
| a todo with quotes and an ampersand is stored as text | Edge     | Medium   | `@todo-list` `@regression`          | Enter on `Practice "magic" & potions` shows that text and makes the count 4. The field is cleared.                                                                                                | The new row is built by concatenating the value into HTML. Quotes and `&` are the realistic characters that would break that string and still should show up as text.          |

## Not selected

| Category                                               | Reason                                                                                                                                                                                                                 |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A separate keyboard suite                              | N/A. Enter is the add path, and that is the add test. The plus icon is `aria-hidden` and is not a control in the tab order. There is no other key handler.                                                             |
| Disabled or read-only controls                         | N/A. Nothing on the page is disabled or read-only.                                                                                                                                                                     |
| Whitespace-only Enter                                  | The visible result is the same blank row as an empty Enter. The value is not trimmed (`" " + value`), and the text check collapses that space, so a second test would not show a different outcome.                    |
| A second copy of a practice item                       | Append has no uniqueness check. The add test already shows a new row is added beside the practice rows. A duplicate string does not take another branch.                                                               |
| Completing or deleting a row that was just added       | Both handlers are delegated on `ul` (`$("ul").on("click", "li"` and `"span"`), so a new row uses the same functions as the practice rows. A second complete test and a second delete test would repeat those handlers. |
| HTML tags in the todo text                             | The same concatenation parses `<b>` as an element. That is a markup bug. The quotes-and-ampersand case is the one that must stay text. Locking the tag case would assert the bug.                                      |
| Clicking the delete span before it is hovered          | The span is `width: 0`, so the click waits until the action timeout. The remove test's width check covers that state. A timeout is not an outcome.                                                                     |
| Sibling delete controls after the row has been removed | The next row slides up under the pointer, so its span opens. That is the hover CSS, not a second delete.                                                                                                               |
| The Home link                                          | Site chrome. It is not a list outcome.                                                                                                                                                                                 |
| Mobile widths                                          | The suite runs Desktop Chrome only. Covering the breakpoints would mean a config change.                                                                                                                               |
