Explored `https://webdriveruniversity.com/AI-Playground/index.html` (title `AI Testing Playground | WebDriver University`) in Chromium at the suite's Desktop Chrome viewport, 1280×720. The heading is `AI Testing Playground`. The path is `/AI-Playground/index.html`. This plan is challenges 1–5. The split is `specs/ai-playground.plan.md` on the roadmap branch. This file does not copy that roadmap.

The describe block is tagged `@ai-testing-playground` and `@ai-testing-playground-basics-a`. Every test is `@regression`. `@smoke` is only the Flaky Loader line `Content loaded successfully!`.

## What the page does

### 1. Dynamic Selectors

The card has `data-testid="dynamic-login-card"`. On load the script inserts a username field, a password field, and a Login button, each with new `cls-` classes. A span reading `Submit Form` is not a button. The result lines are already in the page: `#dynamic-error` (`Invalid credentials`) and `#dynamic-success` (`Login successful`), both `display: none` until a click.

Login trims both values. If both are non-empty, it shows the success line and hides the error. Otherwise it shows the error and hides the success. There is no password check. `ada` / `secret` succeeds. An empty field, a missing password, and whitespace-only fields fail. Values with surrounding spaces succeed, and the fields keep those spaces.

The card is the scope. The accessible names are the placeholders `Username` and `Password`. Another Login button exists on the session challenge, so Login is found inside the card. The classes are not locators.

### 2. Flaky Loader

`Load Content` hides `#flaky-content`, shows `#flaky-loading` (`Loading...`), and after `3000 + random * 5000` milliseconds (3 to 8 seconds) hides the loading line and shows the content. The content is the line `Content loaded successfully!` and the button `Click Me Now`. Both are in the page from the start, under `display: none`. A text check on that sentence passes while the line is still hidden. The wait is visibility. The default assertion timeout is 5 seconds, so the visibility check uses 15 seconds.

`Click Me Now` calls the shared toast with `Flaky button clicked!`. A role lookup does not match that button while the content is hidden, so the locator is `#flaky-action`. Its name is `Click Me Now`.

### 3. Multi-Step Form

`#multi-step-form` is a div. The steps are `#step-1`, `#step-2`, `#step-3`, and `#step-done`. `#step-text` reads `Step 1 of 3`, then `Step 2 of 3`, then `Step 3 of 3`, then an empty string after submit. The captions are not tied to the controls. The same placeholders and the words Next, Back, and Submit appear on other challenges. A hidden step stays in the page, and the two Next buttons share a name, so each control is found inside its step. `Valid email required` appears four times on the page, so that error is found inside the name step.

Step 1 requires a name of at least two words after trim (`Jane` fails, `  Jane Doe  ` passes) and an email matching `^[^\s@]+@[^\s@]+\.[^\s@]+$` (`jane@example` fails, `jane@example.com` passes). Both errors can show together. A failed Next stays on step 1. A later valid Next clears the error and opens step 2.

Step 2 requires a country. The phone is optional and is not checked (`abc` is accepted, and an empty phone is accepted). The menu values are `UK`, `US`, `DE`, and `FR`. Back returns to step 1 and keeps the name and email.

Step 3 comments are optional. The terms checkbox must be checked. Submit without it shows `You must accept the terms` and stays on step 3. Submit with it hides step 3 and shows `Form submitted successfully.`

The email control is `type="email"`. Chromium stores `jane@example.com` as `jane@example.com` before the page reads it, so surrounding spaces on that field are not the page's trim.

### 4. Auto-Dismiss Toast

`#toast` is in the page for the whole visit. It starts as `Notification triggered`, class `toast`, opacity `0`. `toBeVisible()` ignores opacity, so it passes before the toast is shown and after it fades. Trigger Toast sets the text to `Action completed`, adds `show`, and removes `show` after 2 seconds. Opacity fades for about 0.3 seconds in each direction. Right after the click the class and the text are already set and the opacity is still `0`. A text check on its own passes on the first poll while the toast is still transparent. The shown check is opacity `1`. The gone check is opacity `0`, after that shown check. An opacity `0` check that ran before the toast was shown would pass on the first poll. The node stays, and the text stays, after it fades. A second trigger shows it again.

### 5. Re-Enable Delay

`Click Me` starts enabled and `#reenable-status` is empty. The name is exact, because `Click Me Now` contains that text. The click disables the button and sets `Re-enabling in 3s…` (the ellipsis is one character). About one second later the status reads `2s`, then `1s`. About three seconds after the click the button is enabled and the status is `Ready`. The button starts enabled, so an enabled check that ran before the disabled check would pass on the first poll. A second click after `Ready` disables it again. The separate countdown ticks are not asserted. A slow runner can miss `2s` between polls, and `Ready` is the outcome.

## Not automated

| Category                                       | Reason                                                                                                                                                                                   |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A wrong password on Dynamic Selectors          | N/A. Any non-empty pair succeeds. There is no credential to get wrong.                                                                                                                   |
| Password filled and username empty             | The same branch as a missing password: one side of `user && pass` is empty.                                                                                                              |
| A later invalid login after a success          | Each login test checks that the other line is hidden. The class toggle is the same function.                                                                                             |
| The `Submit Form` span                         | It is not a control. The Login button is the control.                                                                                                                                    |
| Login classes                                  | They change on each load. Asserting one would be the bug this challenge is built to cause.                                                                                               |
| The loading line visible in the first moment   | It is shown in the click, before the test can poll. That check passes on the first poll. The content becoming visible is the wait.                                                       |
| Asserting the loader with a text check         | `Content loaded successfully!` is in the page while it is hidden. The check would pass on the first poll.                                                                                |
| Back from the terms step                       | Same back behavior as the country step: the step changes and the fields stay. Verified on the live page. Not a second rule.                                                              |
| Spaces around the email                        | The field is `type="email"`. Chromium stores the value without the surrounding spaces before the page trims it.                                                                          |
| A double space between the two names           | The same split as the surrounding spaces on the login fields. The form accepts `  Jane Doe  ` by that split. The login case is the one that keeps the spaces in the field after success. |
| Comments text                                  | Comments are optional and do not appear in the result. The success path leaves them empty.                                                                                               |
| Keyboard on Next or Submit                     | The controls are buttons. Enter and Space activate the focused button. There is no separate key handler and no form submit.                                                              |
| Each countdown second                          | `Ready` is the outcome. Asserting `2s` and then `1s` races a one-second interval.                                                                                                        |
| `toBeVisible()` or `toBeHidden()` on the toast | Opacity is what changes. Visibility does not.                                                                                                                                            |
| A toast text check before opacity `1`          | The text is set in the click, while opacity is still `0`. The check would pass on the first poll.                                                                                        |

## Runtime

Twenty-two tests. One is `@smoke`. The loader tests wait up to 8 seconds for the content, and the toast and re-enable tests wait for a fade or a 3 second delay. Those waits are the assertion. None of them sleep.
