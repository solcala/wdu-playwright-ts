## What the page does

### 6. Moving Target

`#moving-btn` reads `Catch Me`. It is `position: absolute` inside `#moving-container`. On load, and then every 1500 milliseconds, the script sets `left` and `top` to a random point inside the container. The jumps are instant. There is no transition. Between jumps the button is still, for about 1.5 seconds.

The click calls the shared toast with `Got it!`. That is the same `#toast` as Auto-Dismiss Toast. The text is set in the click, `show` is added, and `show` is removed after 2 seconds. Opacity fades for about 0.3 seconds in each direction. `toBeVisible()` ignores opacity. A text check on `Got it!` passes on the first poll while the toast is still transparent. The shown check is opacity `1`. The gone check is opacity `0`, after that shown check. The node stays, and the text stays, after it fades.

`Catch Me` is the only button with that name. The click is Playwright's click, which retries until the button is stable and then clicks its center. A point saved before a jump is stale. The smoke test does not store a coordinate.

The button starts below the 720px fold. The click scrolls it into view. The position test reads the inline `left` and `top`. It does not need the button in view.

### 7. Conditional Validation

The Email caption is not tied to the field. The placeholder `you@example.com` is also on the invisible-success field, so the field is `#cond-email`. `Valid email required` appears on other challenges, so the error is `#cond-email-err`. Submit is also on the multi-step form and the invisible-success form, so the button is `#cond-submit`. The result line `#cond-result` has no role. Its text changes. It starts empty.

`#cond-extra-wrap` starts with `display: none`. Inside it, `#cond-code` is a text field, placeholder `6-digit code`, `maxlength` 6. A role lookup skips that field while the wrap is hidden. The placeholder is unique and still matches, so that is the locator. The tests read the value in both states. `Valid 6-digit code required` appears once, on `#cond-code-err`.

The code field does not appear when the email is typed. It appears on Submit, and only when the email is valid. The email check trims and uses `^[^\s@]+@[^\s@]+\.[^\s@]+$`. `ada@example` fails. An empty field fails. Both show `Valid email required`, clear the result, and leave the code field hidden.

The field is `type="email"`. Chromium stores a whitespace-only value as empty, and stores `  ada@example.com  ` as `ada@example.com`, before the page reads it. The page's trim is not what removes those spaces.

A valid email on the first Submit sets the result to `Verification required. Please enter the code.` in `#c0392b` (`rgb(192, 57, 43)`) and shows the code field. It does not check the code yet. The email stays.

Any later `input` on the email clears the result text, hides the email error, and, if the code field is showing, hides it, clears the code, and hides the code error. The color on the result is not reset. The input hides the email error even when the new value is still invalid (`still-bad`). Filling the same address again also fires `input`, so it also withdraws the code field. The tests change the address, which is the same listener.

The second Submit, while the code field is showing, trims the code and requires `/^\d{6}$/`. A miss shows `Valid 6-digit code required` and leaves the verification sentence and the code field. `12345` fails. An empty code fails. `abcdef` fails. ` 12345` is six characters, so it fits `maxlength`, and the trim leaves `12345`, so it fails. The field keeps the spaces.

`1234567` does not fit. The field keeps `123456`, and that second Submit succeeds. The success sentence is `Submitted successfully.` in `#1f8f3a` (`rgb(31, 143, 58)`). The code field hides, both fields clear, and the email error and the code error hide. A Submit after that is the empty-email path: the success sentence is cleared and `Valid email required` shows.

`ADA@EXAMPLE.COM` passes the email check. The regex does not fold case.

### 8. Race Condition

`Start Race A` and `Start Race B` are the only buttons with those names. The result is `#race-result`. It starts empty. It has no role.

A click sets the result to `Race A running…` or `Race B running…` immediately. The ellipsis is one character, U+2026. The winner is chosen in a timer of `500 + random * 2000` milliseconds (0.5 to 2.5 seconds). `raceWinner` is set in that timer, not on the click. The first timer to fire sets the winner and the result to `Race A won!` or `Race B won!`. The other timer then does nothing. Three seconds after the win, `raceWinner` is cleared and the result is emptied.

A second click before either timer has fired starts another timer and overwrites the running line. Either name can win. Asserting that Race A always wins flakes. The both-buttons test reads `Race A running…` immediately after the first click, then `Race B running…` immediately after the second. The timer is at least 0.5 seconds, so those checks pass on the first poll. They fail if a click never started. The winner is then `/^Race [AB] won!$/`. The result text is recorded from before either click. Each text change is kept, including two changes in one turn. From the first winner, the next different line has to be empty. Repeated copies of that winner are the same line. An empty check that ran before the win would pass on the first poll, because that is how the result starts.

A click after a winner is set returns immediately, until the three-second clear. A late Race B does not replace `Race A won!`. The test reads that win again on the line before the click. After the clear, the empty line is the same shape as a stolen win that has also been cleared. The test remembers if any other line was seen, and the empty result passes only when it was not. After the clear, Race A can win again.

A single Race A click is deterministic: the only timer is Race A, so the result is `Race A won!`. The running line is not the outcome of that test.

### 9. Lazy-Rendered Element

`#lazy-element` is in the page from the start, with `display: none`. The paragraph inside it already reads `I just appeared! Selector:` and `#lazy-selector` is empty. `getByText('I just appeared!')` matches that paragraph once. A text check on the sentence passes while it is hidden. The wait is visibility. The click removes `hidden` from the div, which is what shows the paragraph, and sets the code text to `#lazy-` plus `Math.floor(Math.random() * 9999)` (0 through 9998). The check is `/^#lazy-\d+$/`, not one number.

The click is synchronous. A second click sets a new number and does not hide the element. The same number can be drawn twice, so the second test does not assert that the text changed. The node is never removed. It is attached before the click.

## Runtime

Twenty-two tests. One is `@smoke`. The moving-button toast waits for a fade, the race waits for a timer of up to 2.5 seconds and a clear of 3 seconds, and the position check waits until the offset changes. Those waits are the assertion. None of them sleep.
