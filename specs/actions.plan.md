# Actions plan

Explored `https://webdriveruniversity.com/Actions/index.html` (title `WebDriver | Actions`) in Chromium at the suite's Desktop Chrome viewport, 1280×720, through the existing bot-wall path. The page is one heading and four mouse widgets. There are no inputs.

| Widget         | What the page actually does                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Drag and drop  | `#draggable` is a jQuery UI draggable. Dropping it on `#droppable` sets the target text to `Dropped!`, adds `ui-state-highlight` on the target, and adds `was-dropped` on the source. Both labels turn green (`rgb(16, 185, 129)`). Nothing removes that state.                                                                                                                              |
| Double click   | `#double-click` listens for `dblclick` and toggles the class token `double`. That token turns the heading green. A single click does nothing. The resting class is `div-double-click`, which also contains the letters "double".                                                                                                                                                             |
| Hover menus    | Three buttons: `Hover Over Me First!`, `Hover Over Me Second!`, `Hover Over Me Third!`. CSS `.dropdown:hover .dropdown-content` shows that menu's links and leaves the others `display: none`. Moving the pointer away hides them. Every link has class `list-alert` and alerts `Well done you clicked on the link!`. The third menu is the only one with `Link 2`.                          |
| Click and hold | `#click-box` on `mousedown` sets the text to `Well done! keep holding that click now.....` and the background to `#10b981`. `mouseup` on that same element sets `Dont release me!!!` and the background to `#f45950`. `mouseup` elsewhere does not run that handler. The computed font size is already 30px before the press, so the script's `fontSize` assignment is not a visible change. |

Locators, in the project order: the hover controls are buttons, so they use `getByRole` with an exact name. Their links are not unique and are hidden until hover, so each link is scoped to that button's menu and matched with `includeHidden`. The drag source, drop target, double-click box, and click-and-hold box have no accessible role; each has a unique id. The duplicated id `div-drag-drop-thumbnail` is not used. The page heading is the miss target and the "pointer moved away" target.

`locator.dragTo` does fire the jQuery UI drop at this viewport. A drag onto the heading ends above the target, and the drop handler does not run.

## Cases

Tags: `@actions` on every test. `@smoke` only on the one successful outcome for each widget. `@regression` on every other chosen case. Smoke tests are not also tagged `@regression`, matching Button Clicks.

| Case                                                 | Category | Priority | Tags                     | What it checks                                                                                                                                                                                                                              | Why this one                                                                                                                              |
| ---------------------------------------------------- | -------- | -------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| dragging onto the target shows Dropped               | Positive | Critical | `@actions` `@smoke`      | The target starts as `DROP HERE!`. After the drag it reads `Dropped!`, has `ui-state-highlight`, and its text is green. The source has `was-dropped` and its text is green.                                                                 | The drop handler is the widget's only success path.                                                                                       |
| a drag that misses the target does not drop          | Negative | High     | `@actions` `@regression` | Dragging onto the page heading moves the box above its start. The target still reads `DROP HERE!` and neither success class is added.                                                                                                       | A drag that never lands would look the same if the test only checked the text. The move proves the gesture happened and was rejected.     |
| a drop stays after the box is dragged off the target | Edge     | High     | `@actions` `@regression` | Drop onto the target, then drag the box onto the heading. The target still reads `Dropped!` and keeps `ui-state-highlight`.                                                                                                                 | The handler never resets. A later change that cleared the target on drag-out would be invisible to the success test.                      |
| double click turns the box on                        | Positive | Critical | `@actions` `@smoke`      | One double click adds the `double` token. The heading color becomes `rgb(16, 185, 129)`.                                                                                                                                                    | This is the widget's only success path. The color is the visible result of the class.                                                     |
| a single click leaves the double click box off       | Negative | High     | `@actions` `@regression` | One click leaves the `double` token absent and the heading `rgb(244, 89, 80)`.                                                                                                                                                              | The listener is `dblclick`, not `click`. The success test would still pass if a single click also toggled the class.                      |
| a second double click turns the box off              | Edge     | High     | `@actions` `@regression` | Double click turns the box on. A second double click removes `double` and returns the heading to `rgb(244, 89, 80)`.                                                                                                                        | The handler is `toggleClass`, not `addClass`. The success test only sees the first toggle.                                                |
| the first hover link shows the click alert           | Positive | Critical | `@actions` `@smoke`      | `Link 1` under the first button starts hidden, is visible after hover, and the click alerts `Well done you clicked on the link!`.                                                                                                           | One menu is enough for the alert path. The other menus share that handler.                                                                |
| a hover opens only that menu                         | Positive | High     | `@actions` `@regression` | Each hover shows only that menu's links: `Link 1` on the first, `Link 1` on the second, and `Link 1` plus `Link 2` on the third. The others stay hidden.                                                                                    | The second button is marked up differently (`dropdown` without the extra `hover` class, invalid `float`). Each menu can break on its own. |
| moving the pointer away hides the open menu          | Edge     | Medium   | `@actions` `@regression` | After a hover shows a menu, moving the pointer to the page heading hides that menu's links. Checked for all three menus.                                                                                                                    | The menus are CSS `:hover` only. A menu that stayed open would fail this and not the click test.                                          |
| Link 2 shows the click alert                         | Positive | Medium   | `@actions` `@regression` | Hovering the third menu and clicking `Link 2` alerts `Well done you clicked on the link!`.                                                                                                                                                  | `Link 2` is the only extra link. The other `Link 1` clicks repeat the same `list-alert` handler, so they are not separate tests.          |
| pressing then releasing the box shows both messages  | Positive | Critical | `@actions` `@smoke`      | The box starts as `Click and Hold!`. While the button is down the text is `Well done! keep holding that click now.....` and the background is `rgb(16, 185, 129)`. Releasing over the box sets `Dont release me!!!` and `rgb(244, 89, 80)`. | Press and release are one gesture. The release text only exists after the press, so they stay in one test.                                |
| releasing outside the box keeps the hold message     | Edge     | High     | `@actions` `@regression` | Press the box, move the pointer to the page heading, then release. The hold text and green background stay.                                                                                                                                 | `mouseup` is bound to `#click-box` only. Releasing on the box is the success test; releasing off it is the other real outcome.            |

The class check for double click matches the token `double`, not the substring inside `div-double-click`.

## Not selected

| Category                                                 | Reason                                                                                                                                                                                           |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Empty, invalid, or whitespace input                      | No fields and no form. Nothing to reject.                                                                                                                                                        |
| Disabled or read-only controls                           | None of the widgets are disabled.                                                                                                                                                                |
| Keyboard activation                                      | Not implemented. Menus open from `.dropdown:hover` only. Drag, double click, and click-and-hold are mouse handlers. A keyboard failure would be a new requirement, not a broken one.             |
| A different alert per link                               | Every `.list-alert` calls `alert("Well done you clicked on the link!")`. Repeating that click for the second and third `Link 1` does not add an outcome. Their visibility is the isolation case. |
| Clicking a link while it is hidden                       | The link is `display: none`, so the click waits until the action timeout. The hidden check covers that state. A timeout is not an outcome.                                                       |
| Undo the double click with a single click                | `dblclick` is the only listener. A single click is not an undo. The single-click case covers the off state, and the second double click covers the toggle.                                       |
| A reset control for the drop                             | There is no reset. The sticky-drop case is the observed behavior.                                                                                                                                |
| Distinct failure text for a missed drag or a short click | The page shows no error. The missed drag leaves `DROP HERE!`. A short click on the hold box is just a press plus a release, which is the success case.                                           |
| Navbar and the brand link                                | Site chrome, not an actions outcome.                                                                                                                                                             |
| `$("#menu").menu()`                                      | There is no `#menu` element. The script does nothing.                                                                                                                                            |
| Click-and-hold font size                                 | It is 30px before the press, so the assignment does not change what the user sees.                                                                                                               |
| Mobile widths                                            | The suite runs Desktop Chrome only. Covering the breakpoints would mean a config change.                                                                                                         |
