# File Upload plan

Explored `https://webdriveruniversity.com/File-Upload/index.html` (title `File Upload`) in Chromium at the suite's Desktop Chrome viewport, 1280×720, through the existing bot-wall path. The page is one form. There is no upload endpoint.

| Control    | What the page actually does                                                                                                                                                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| File input | `#myFile` is `<input type="file" name="filename">`. It has no label, no `accept`, no `multiple`, and no `required`. Chromium exposes it as a button named `Choose File`. That name stays `Choose File` after a file is chosen. The DOM value is `C:\fakepath\` plus the file name. The value is empty until a file is chosen. |
| Submit     | `#submit-button` is `<input type="submit">` with no `value`. Its accessible name is `Submit`. `onclick` calls `fileSubmitted()`.                                                                                                                                                                                              |
| The check  | `fileSubmitted()` reads `document.getElementById("myFile").value.length`. Length `0` alerts `You need to select a file to upload!`. Any other length alerts `Your file has now been uploaded!`. The function does not read the file, its size, or its type, and it does not return `false`.                                   |
| The form   | The form has no `action`, no `method`, and no `enctype`. After the alert, the browser GETs this same page. The query is `filename` plus the chosen name. A space becomes `+`. An empty choice becomes `filename=` with nothing after the equals sign. The file bytes are not in the request. The reload clears the input.     |

`getByRole('button', { name: 'Choose File' })` is the file input. `getByRole('button', { name: 'Submit' })` is the submit input. Both names are unique. Enter on the file input opens the browser's file chooser and does not call `fileSubmitted()`. Enter or Space on Submit does call it. Closing the alert with OK or with dismiss both let the GET continue: `alert()` does not branch on how the dialog was closed.

Dialog methods register `page.waitForEvent('dialog')` before the click or keypress that opens the alert. The alert is gone if nothing is listening.

Chosen files are the small fixtures under `test-data/file-upload/`. The spec passes paths relative to the project root. Nothing uses an absolute path.

## Cases

Tags: `@file-upload` on the describe block, `@regression` on every test. `@smoke` only on the one successful upload, so that test carries both.

| Case                                              | Category | Priority | Tags                                  | What it checks                                                                                                                                                                     | Why this one                                                                                                                                        |
| ------------------------------------------------- | -------- | -------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| the upload form starts empty                      | Positive | Medium   | `@file-upload` `@regression`          | The title is `File Upload`. The headings are visible. The file input is empty and enabled. Submit is enabled.                                                                      | The other tests submit. This is the state they start from: an empty control, not a file left over from another test.                                |
| submitting a chosen file shows it was uploaded    | Positive | Critical | `@file-upload` `@smoke` `@regression` | `notes.txt` is `C:\fakepath\notes.txt`. Submit alerts `Your file has now been uploaded!`. The URL ends with `?filename=notes.txt`. The reloaded input is empty. The title remains. | The only success path. The query is the evidence the form submitted the name. The empty input is the reload: the choice does not stick.             |
| pressing Enter on Submit uploads the chosen file  | Positive | High     | `@file-upload` `@regression`          | With `notes.txt` chosen, Enter on Submit alerts `Your file has now been uploaded!` and the URL ends with `?filename=notes.txt`.                                                    | Submit is a real submit input, so the keyboard path is the page's, not a new requirement. The click test would still pass if Enter did nothing.     |
| submitting with no file asks for a file           | Negative | Critical | `@file-upload` `@regression`          | Submit with an empty input alerts `You need to select a file to upload!`. Submit alerts the uploaded message. The URL ends with `?filename=second.txt`.                          | The check reads the current value. ## Not selected

| Category                                              | Reason                                                                                                                                                                                                                           |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| File type or an `accept` filter                       | N/A. The input has no `accept`. `fileSubmitted()` does not look at the type. A `.png` would take the same branch as `notes.txt`.                                                                                                 |
| Multiple files                                        | N/A. `multiple` is false. The control accepts one file. Setting two is rejected before the page script runs.                                                                                                                     |
| Choosing a directory                                  | N/A. The input has no `webkitdirectory`.                                                                                                                                                                                         |
| Disabled or read-only controls                        | N/A. The file input and Submit are enabled. There is no read-only state on a file input.                                                                                                                                         |
| A server that rejects the upload                      | N/A. There is no upload URL. The form GETs this page and sends the file name only. The bytes are not in the request, so there is no HTTP error to assert.                                                                        |
| A size limit or a file that is too large              | N/A. The script never reads the size or the contents. A long name is not truncated: a 200-character name was submitted whole. The fixtures stay small because the page does not use the bytes.                                   |
| Drag and drop onto the page                           | N/A. The page has no drop handler. Dropping a file on the native control is the browser chooser, not a page outcome.                                                                                                             |
| Dismissing the alert instead of accepting it          | N/A as its own outcome. `alert()` does not return a value the page uses. Dismiss and OK both let the GET continue, and the query is the same. The tests accept the alert.                                                        |
| Enter on the file input                               | Not a submit path. Enter opens the browser file chooser and does not call `fileSubmitted()`. A timeout waiting for an alert that never comes is not an outcome.                                                                  |
| Space on Submit                                       | The same native button activation as Enter, with the same alert and the same `?filename=notes.txt`. Enter is the test.                                                                                                           |
| A second submit after a successful one                | The reload clears the input, which the success test checks. The next submit is the empty-file case, which has its own test.                                                                                                      |
| Other names (`café.txt`, `a+b.txt`, `a&b.txt`, `../`) | The same success branch. The name is copied into the query and form-encoded (`caf%C3%A9.txt`, `a%2Bb.txt`, `a%26b.txt`, `..%2Fnotes.txt`). The space case is the encoding check. Repeating it for each character adds no branch. |
| Navbar and the brand link                             | Site chrome, not an upload outcome.                                                                                                                                                                                              |
